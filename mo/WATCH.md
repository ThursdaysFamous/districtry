# WATCH.md — Missouri's watch calendar and deferred measurements

Two things live here: *when to look* for boundary and roster changes in this instance's
sources, and the measurements this instance has taken but not yet acted on. The repo's
`docs/REDISTRICTING_RUNBOOK.md` is *what to do* when a boundary changes. Update the
"Last done" column each time you complete a row — a checkpoint with a stale date is a
checkpoint that didn't happen.

## Re-check plan for each data file the app reads

The three roster jobs are in the standing table above. The files below have no job, because a
weekly job on a boundary would almost always find nothing to change. Each row says what moves the
file and when to look. A builder's `--check` proves a file matches what it was built from; it
never proves the source is still current.

| Cadence | File | The clock, and why it is that one | Last done |
|---|---|---|---|
| **After the 3 November 2026 referendum**, annually when TIGERweb rolls its congressional vintage, and on any court order | `congress-districts.json` | The 2022 map is drawn from TIGERweb layer 4, and the builder refuses if that layer stops being the 119th Congress's map, because TIGERweb renumbers its layers when a vintage rolls. The referendum decides whether a different map applies from 2028 | 2026-10-21 (built from the 2022 map) |
| **Annually**, and on any court order | `mo-senate-districts.json`, `mo-house-districts.json` | The 2022 plans are in force until the plans drawn after the 2030 census. Both come from the redistricting office's own map service, and the builder refuses if a layer stops being that office's or the Senate layer stops describing the 2022 plan, so a replacement is read by a person before it is drawn | **_(never)_**, built 2026-10-21 |
| **Annually**, when TIGERweb publishes a new county vintage | `state-counties.json`, `mo-state-outline.json`, `metro-outline.json` | All three come from the same 115-county TIGERweb fabric, and the two outlines are that fabric dissolved (the state whole, and the counties whose commission lines are drawn), so they share one clock. `mo/scripts/build_metro_outline.py --check` tests the state outline against its 115 inside anchors and its 23 outside anchors in all eight neighbouring states, and the coverage ring against an inside anchor in each drawn county and an outside anchor in every other, so it would catch a lost county and would not notice a redrawn line | **_(never)_**, built 2026-10-21 |
| **When a county's election authority answers a letter, and annually** | `mo-commission-districts.json`, `mo-commission-counties.json` | Each drawn county's two districts come from that county's own map, file or clerk, and RSMo 49.010 has the commission redraw them after each census, so they move about once a decade and not on a date the state sets. `mo/scripts/build_mo_commission_districts.py` holds both files to its sources and to the roster's seats; the yearly look is for a county that has redrawn, and a letter's answer can both add a county and correct one. A county joins the coverage ring in the same change (row below) | 2026-10-26 (30 counties) |
| **Annually**, and in the same change as any new Missouri layer or roster | `coverage-gaps.json` | This file is emitted from the guidebook's gaps block, and `build_coverage_gaps.py --check` compares the two on every pull request, so the file cannot drift from the record. The yearly clock is for the RECORD: each gap rests on a measurement with a date, and a publisher that starts publishing moves that finding with nothing to detect it | 2026-10-21 (written with the instance) |
