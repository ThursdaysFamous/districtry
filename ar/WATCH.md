# WATCH.md — Arkansas's watch calendar and deferred measurements

Two things live here: *when to look* for boundary and roster changes in this instance's
sources, and the measurements this instance has taken but not yet acted on. The repo's
`docs/REDISTRICTING_RUNBOOK.md` is *what to do* when a boundary changes. Update the
"Last done" column each time you complete a row — a checkpoint with a stale date is a
checkpoint that didn't happen.

## Re-check plan for each data file the app reads

The three roster jobs are in the standing table above, and the weekly county-officials job also
watches `ar-quorum-court-districts.json`'s source for a redraw. The files below have no job,
because a weekly job on a boundary would almost always find nothing to change. Each row says what
moves the file and when to look. A builder's `--check` proves a file matches what it was built
from; it never proves the source is still current.

| Cadence | File | The clock, and why it is that one | Last done |
|---|---|---|---|
| **Annually**, when TIGERweb rolls its congressional vintage, and on any redistricting act or court-ordered redraw | `congress-districts.json` | The General Assembly draws Arkansas's four congressional districts by act, so an act or a court order is what moves them. The file is TIGERweb layer 0 (the 120th Congress), measured identical to layer 4 (the 119th) for Arkansas on 2026-10-13, so the national change on 3 January 2027 does not move it. Re-run `ar/scripts/build_legislative_boundaries.py`, which re-measures the 25 m fidelity ceiling | **_(never)_**, built 2026-10-13 |
| **After each decennial census** (the 2030 census's districts are drawn in 2031), and on any court-ordered redraw | `ar-senate-districts.json`, `ar-house-districts.json` | The Board of Apportionment (the Governor, the Secretary of State and the Attorney General) draws both chambers after each census under article 8 of the state constitution, so a census or a court order is the clock rather than a legislative session. Rebuild both together with `ar/scripts/build_legislative_boundaries.py`, never one chamber alone | **_(never)_**, built 2026-10-13 |
| **Annually**, when TIGERweb publishes a new county vintage | `state-counties.json`, `metro-outline.json` | Both come from the same 75-county TIGERweb fabric, and the outline is that fabric dissolved, so they share one clock. `ar/scripts/build_metro_outline.py --check` tests the shipped ring against its 75 inside anchors, so it would catch a lost county and would not notice a redrawn line. Re-run `ar/scripts/build_state_counties.py` and `ar/scripts/build_metro_outline.py` against the new vintage and compare, then rebuild `fleet-outlines.json` at the root | **_(never)_**, built 2026-10-13 |
| **Annually**, and in the same change as any new Arkansas layer or roster | `coverage-gaps.json` | This file is emitted from the guidebook's gaps block, and `build_coverage_gaps.py --check` compares the two on every pull request, so the file cannot drift from the record. The yearly clock is for the RECORD: each gap rests on a measurement with a date, and a publisher that starts publishing moves that finding with nothing to detect it | 2026-10-13; 2026-10-16 (`ar-appeals-judges` and `ar-circuit-judges` added with the court layers; `ar-fire-district-boards` added with the fire district layer) |
| **Annually**, and on any word that a county court has changed its townships | `ar-townships.json` | A county court divides its county into townships and changes their lines by order (Arkansas Code 14-14-401), at no fixed time, and the state's mapping office republishes its township layer when one does. The layer carries no edit date, no description and no record of changes (read 2026-10-15), so nothing says when it moved. Run `ar/scripts/build_ar_townships.py --watch`, which reads the live layer's names and areas, no geometry, and compares them with the fingerprint recorded when the shipped file was built; on a difference, rebuild with `ar/scripts/build_ar_townships.py` and say which counties moved | **_(never)_**, built 2026-10-15 |
| **Quarterly** | `ar-precincts.json` | Counties send the state new precincts as they change them, and the Arkansas GIS Office's layer is updated as they arrive; a date of the county's last change is on half the records only, so the layer cannot say which counties moved. Run `ar/scripts/build_ar_precincts.py --watch`, which takes about fifteen minutes because the office's open-data host asks for 60 seconds between requests. `--watch` reads every record's key, name, county and area, with no geometry, and compares them with the fingerprint recorded when the shipped file was built; on a change it names the counties whose precinct counts moved. Then rebuild with the builder, which re-runs the exact count, the every-county check, the 6,000-point agreement gate and the per-county cover check and refuses to write if any fails. A new count is changed by hand, in the builder's `expect` and in `data_files.geometry`, and never widened into a range; check the precinct anchor in the worksheet, bump `cache_name` because the file is cache-first, and say which counties moved. The builder also expects exactly eight records that are further pieces of seven precincts, so a precinct newly published in pieces stops the watch and a rebuild until someone reads the layer | 2026-10-15 (built: 2,920 precincts in 75 counties; `--watch` unchanged the same day) |
| **Annually**, after each regular session of the General Assembly, and on any act that moves a county between districts or circuits or changes a circuit's judgeships | `ar-appeals-districts.json`, `ar-judicial-circuits.json` | The General Assembly sets both by act: Act 1812 of 2003 names each Court of Appeals district's counties, and acts add circuit judgeships, as Act 220 of 2025 does for the 19th West (the dated row below). The official Code cannot be read here (LexisNexis's copy needs a browser's scripts, and the two free copies tried refuse this project's client), so the re-check re-reads the pages and the two map layers `ar/data/source/courts/README.md` lists, asking `scripts/robots_policy.py` first at every hop, reduces them into that folder as its "How to re-read" section says, and re-runs `ar/scripts/build_ar_court_districts.py`. The build stops if a judge serves only some of a circuit's counties, if the statewide judge count is not the one it pins, if either state layer puts a county in a different unit, or if the court order's sentences or the act's lines no longer read as they did. A changed count is made by hand in the builder and in `data_files.geometry`, and both files are cache-first, so bump `cache_name` | 2026-10-16 (built: 7 districts, 28 circuits, 126 judges) |
| **On 1 January 2027** | `ar-judicial-circuits.json` | The 19th West's eighth judgeship (Act 220 of 2025) takes office that day, so its card, which says seven judges, becomes one short. Re-read the circuit judge directory once it lists the eighth judge, change `CIRCUIT_JUDGES` in `ar/scripts/build_ar_court_districts.py` from 126 to 127, rebuild, and bump `cache_name` | **_(never)_** |
| **Quarterly**, and after each decennial census | `ar-school-board-zones.json` | A board's zones change when it redraws them after a census and when it moves seats to at large: Act 424 of 2023 lets a board return to electing every member at large, and by 9 April 2026 twelve had resolved to, eight of them seat by seat as terms end. The Secretary of State compiles the zones and the Arkansas GIS Office publishes them; the layer carries no edit date the builder can read, and its record of changes is the office's blog posts (the post of 9 April 2026 now redirects and was read through the Internet Archive). Run `ar/scripts/build_ar_school_board_districts.py --watch`, which reads every zone's attributes with no geometry, waits 60 seconds between requests as the office's open-data host asks, and compares a fingerprint of each zone's key, label, board and area with the one recorded when the shipped file was built. On a change it names the boards whose zone counts moved: rebuild, bump `cache_name` because the file is cache-first, and say which boards moved. A change to one of the eight boards moving to at large stops the run until the office's notes are re-read and the builder's table and the card's sentence change together | 2026-10-16 (built: 965 zones on 176 boards) |
| **Quarterly** | `ar-fire-districts.json` | State law has each fire district keep a certified map and send it to the Arkansas GIS Office (A.C.A. § 12-10-329, as the layer's own description puts it), which updates its layer as maps arrive; 699 of the 973 records carry the same date, 21 September 2023, so the dates cannot say which districts moved. Run `ar/scripts/build_ar_fire_districts.py --watch`, which reads every record's name, counties and area with no geometry, waits 60 seconds between requests as the office's open-data host asks, and compares a fingerprint of them with the one recorded when the shipped file was built; on a change it names the sets of counties whose district counts moved. Rebuild with the builder, which re-runs the exact counts, the Siloam Springs join, the four records that label ground, the county names, the agreement gate and the per-county coverage check and refuses to write if any fails; bump `cache_name` because the file is cache-first, and say which districts moved. A new record that labels ground, or a record that names no county, stops the run until someone reads the layer. Nobody who runs a district is named (gap `ar-fire-district-boards`); a letter asking the state's Office of Fire Protection Services which districts elect commissioners, and who they are, is NOT YET ASKED — DRAFTED 2026-10-21 (Ask ar-adem-fire-districts in `docs/ASK_DRAFTS.md`); record its send date and any reply here and in the gap the day each happens | 2026-10-16 (built: 971 districts in 135 sets of counties) |
| **Weekly**, by `.github/workflows/watch-city-council-pages.yml`, and by hand again once the cities' pages list the winners of the 3 November 2026 general election | `ar-city-councils.json` | Each of the 19 cities lists its own mayor and council and changes the page when a seat changes hands, at no fixed time; city contests are on the state's November general election ballot (measured in the 2024 results), so the weeks after an election are when most pages move. The weekly job runs `ar/scripts/build_ar_city_councils.py --watch`, which re-reads every page the seats file cites, asking robots.txt first, reports any name no longer on its page and any page it cannot read, and opens or updates one tracking issue for all five states, "City council pages need a re-read", which the next run that reads every page and finds every name closes; the same command can be run by hand. On a report, read the city's page, change `ar/data/source/ar-city-council-seats.json` by hand (a new member, a changed seat, or the page's own spelling as `as`), and rebuild with the builder, which re-reads every page and refuses to write unless every name is on the page it cites. A city that adds or drops a seat changes `SEATS` in the builder; one that starts or stops electing by ward changes the seats' `by`, which moves the ward map too (the next row) and `WARD_MAPS` in `scripts/build_eam_status.py`. Cabot's site drops some connections, so a NOT READ line for it is worth a second run | 2026-10-16 (built: 174 seats in 19 cities, every name found on its page) |
| **Quarterly**, and after each decennial census, when cities redraw their wards | `ar-city-wards.json` | A city redraws its wards by ordinance, usually after a census, and the Arkansas GIS Office's map of municipal wards takes the change when the city sends it; the layer's dates cannot say which plan is current (one is not a date at all). Run `ar/scripts/build_ar_city_wards.py --watch`, which reads the twelve cities' ward records with no geometry and compares them with the fingerprint recorded when the shipped file was built; on a change, rebuild with the builder, bump `cache_name` because the file is cache-first, and run `ar/scripts/build_ar_city_councils.py --check`, which holds every drawn ward to a seat its voters elect | 2026-10-16 (built: 56 wards in 12 cities) |
