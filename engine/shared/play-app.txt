/* THE GOOGLE PLAY APP'S MARK, in ONE copy, for the pages that show a
   support link or a link to this project's code on GitHub: every app,
   every sub-page and the root pages. The installed app's launcher (/app/) carries it too,
   though it shows no support link, because a place shared into the app
   arrives there (see below).

   districtry's Android app on Google Play is this site in a full-screen
   Chrome window (a Trusted Web Activity), so it shows these same pages.
   Google Play's Payments policy does not let an app lead a reader to a
   payment method other than Google's own billing, and Google applies that
   to donations: in February 2022 it rejected an update of StreetComplete,
   an open-source map app, for asking for donations, rejected it again once
   the donation links were gone and a link to the project's GitHub page,
   which asks for donations, was left, and accepted it when that link went
   too (github.com/streetcomplete/StreetComplete/issues/3768). So inside the
   Play app the links to GitHub Sponsors and to the sponsorship page are
   hidden. The website keeps them, and so does a copy installed from the
   browser's own menu, which no store reviews.

   THE LINK TO THIS PROJECT'S CODE ON GITHUB IS HIDDEN TOO (Adam,
   2026-11-01, after the Play testing service's report pointed at it): the
   repository's page shows a Sponsor button, which is the link StreetComplete
   was refused for. Only a link to the repository itself is hidden, written
   with or without its closing slash. A link to one file or to the issue form
   in the repository stays, because it is how a reader reaches a named
   document or reports a mistake, and the app's report form also sends by
   e-mail. A sentence that reads wrong without its link wraps the words in
   .dst-play-hide, which is hidden with them. scripts/build_manifests.py
   --check fails on a served page that links the repository and carries no
   copy of this block.

   THIS BLOCK IS ITS OWN SCRIPT ELEMENT on every page, never a second
   block inside the theme script, because scripts/question_page.py copies a
   sources page's theme script into the question pages it generates and
   adds this block beside it by itself, so a page that carries both never
   carries this one twice.

   HOW A WINDOW IS KNOWN TO BE THE PLAY APP. The app is built to open
   /app/?ref=play, and the launcher passes ref=play on, and nothing else, to
   the page it opens: a URL is how the Trusted Web Activity documentation
   says an app passes data to its pages. A page whose referrer is the app
   itself (android-app://com.districtry.app, the package name the setup
   guide builds) is marked too. Chrome names the Android app that opened a
   page as its referrer, which is how a link tapped in Gmail arrives as
   android-app://com.google.android.gm, so this should cover a shared link
   opened straight into the app rather than through its icon. A place shared
   from another app's Share menu takes that path into the LAUNCHER (the
   manifest's share_target), which hands on with location.replace, so the
   page it opens sees the launcher as its referrer rather than the app: the
   launcher carries this block for that reason, and passes ref=play on when
   it finds the mark. The referrer path is not yet measured on a phone; the
   first is the one the app's own launches take, and both are tested here
   with the referrer stood in for. Either sets a mark in session
   storage, so every later page in the same window (another state, a sources
   page, the front page) hides the links as well, and the mark goes when the
   app is closed. Session storage belongs to one window, so the mark never
   reaches the reader's ordinary browser tabs.

   WHAT IS HIDDEN is matched by address rather than by a class, so a support
   link added later to any page carrying this block is hidden in the Play app
   without anyone remembering to mark it: every link to github.com/sponsors
   or to sponsorship.html, and the paragraph or list item around one, because
   a sentence asking for sponsorship reads wrong with its link taken out.
   The :has() selectors are a rule of their own because a browser that does
   not know :has() drops every selector in a rule that names it, and the
   app panel's sponsorship sentence, .dpf-support, is named by class in the
   first rule for that browser.

   It runs in the head, before first paint, so the links never flash, and an
   ordinary visit adds no style at all. */
(function () {
  var opened = /(?:^|&)ref=play(?:&|$)/.test(location.search.slice(1)) ||
    /^android-app:\/\/com\.districtry\.app(?:\/|$)/.test(document.referrer || "");
  var marked = opened;
  try {
    if (opened) sessionStorage.setItem("districtry-play-app", "1");
    else marked = sessionStorage.getItem("districtry-play-app") === "1";
  } catch (e) { /* blocked storage: only the page the app opened is marked */ }
  if (!marked) return;
  document.documentElement.classList.add("dst-play-app");
  var css = document.createElement("style");
  css.textContent =
    ".dst-play-app a[href*=\"github.com/sponsors\"]," +
    ".dst-play-app a[href*=\"sponsorship.html\"]," +
    ".dst-play-app a[href$=\"github.com/ThursdaysFamous/districtry\"]," +
    ".dst-play-app a[href$=\"github.com/ThursdaysFamous/districtry/\"]," +
    ".dst-play-app .dpf-support,.dst-play-app .dst-play-hide{display:none!important}" +
    ".dst-play-app p:has(a[href*=\"github.com/sponsors\"])," +
    ".dst-play-app li:has(a[href*=\"github.com/sponsors\"])," +
    ".dst-play-app li:has(a[href*=\"sponsorship.html\"])," +
    ".dst-play-app li:has(> a[href$=\"github.com/ThursdaysFamous/districtry\"])," +
    ".dst-play-app li:has(> a[href$=\"github.com/ThursdaysFamous/districtry/\"]){display:none!important}";
  document.head.appendChild(css);
})();
