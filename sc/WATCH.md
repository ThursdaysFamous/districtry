# WATCH.md — South Carolina's watch calendar and deferred measurements

Two things live here: *when to look* for boundary and roster changes in this instance's
sources, and the measurements this instance has taken but not yet acted on. The repo's
`docs/REDISTRICTING_RUNBOOK.md` is *what to do* when a boundary changes. Update the
"Last done" column each time you complete a row — a checkpoint with a stale date is a
checkpoint that didn't happen.

---

|---|---|---|---|

## Re-check plan for each data file the app reads

The four roster files are rewritten by the weekly jobs in the standing table above, and the
council district map is watched by one of them. The six files below have no job, because a
weekly job on a boundary would almost always find nothing to change. Each row says what moves
the file and when to look. A `--check` proves a file matches what it was built from; it never
proves the source is still current.

| Cadence | File | The clock, and why it is that one | Last done |
|---|---|---|---|
| **Annually**, when TIGERweb rolls its congressional vintage, and on any court-ordered redraw | `congress-districts.json` | The file ships TIGERweb layer 0, the 120th Congress's map, which is right here because South Carolina did not redraw for 2026: layer 0 and the 119th's layer 4 carry the same seven districts and differ by under 0.001% of any district's area (measured 2026-10-10). **A mid-decade redraw was attempted and stopped**: H. 5683, a new congressional map filed after the Supreme Court's Callais decision, passed the House on 20 May 2026, and on 26 May the Senate voted 26-18 to continue it, so the 2026 election uses the existing map (bill history read 2026-10-11). The Senate's extraordinary session can sit until 8 November 2026, and a new General Assembly meets in January 2027 and could redraw for 2028: read the bill's history after the extraordinary session ends and at the new session's start. The district FIELD is versioned and the old one is removed on a roll (a query naming the retired field answers HTTP 400), so a vintage roll needs the builder's field list and the app's `CONGRESS_DISTRICT_FIELDS` changed together. A redraw needs the North Carolina check first: if the new map is for a later Congress than the members now serving, ship the map they were elected from until the new Congress is sworn in | **_(never)_**, built 2026-10-10 |
| **After each decennial census** (next: 2031–2032), and on any court-ordered redraw | `sc-senate-districts.json`, `sc-house-districts.json` | The General Assembly draws both chambers. Senators serve four-year terms and House members two, so a new House map is first used at a general election and a new Senate map at the next one that elects the whole Senate. All three legislative files ship from one mapshaper run (`sc/scripts/build_legislative_boundaries.py`), which re-measures the 25 m fidelity ceiling on every build | **_(never)_**, built 2026-10-10 |
| **Annually**, when TIGERweb publishes a new county vintage | `state-counties.json`, `metro-outline.json` | Both come from the same 46-county fabric, and the outline is that fabric dissolved, so they share one clock. County lines in South Carolina move essentially never; what moves is TIGER's digitisation of them. `sc/scripts/build_metro_outline.py --check` tests the shipped ring against its 46 inside anchors, so it would catch a lost county and would not notice a redrawn line. Re-run `sc/scripts/build_state_counties.py` and `sc/scripts/build_metro_outline.py` against the new vintage and compare | **_(never)_**, built 2026-10-10 |
| **Weekly**, by the watch in `update-sc-county-council-roster.yml`, and **after each decennial census** (next: 2031–2032) when every county redraws | `sc-county-council-districts.json` | Each county council adopts its own districts by ordinance, so a county can redraw in any year, and after a census all 46 do. The watch compares the state's live layer with the fingerprint recorded at build time (each county's district numbers, ordinance, effective date and areas) and opens an issue on any difference. A rebuild is by hand on purpose: a new map changes which seat a certified winner holds, so a person reads the roster beside it | 2026-10-11 (built) |
| **Annually**, on the TIGERweb vintage roll | `tribal-areas.json` (2 areas, the Catawba Indian Nation's) | *Not a redistricting at all* — tribal land changes when the United States takes land into trust, which is published on no calendar. `scripts/build_tribal_areas.py --check` re-derives the shipped file from `data/tribal-government-join.json` and the BIA directory OFFLINE, so it proves the join and NEVER that the Census has not added or removed an area — only a rebuild does that (`python3 scripts/build_tribal_areas.py --state "South Carolina" --tag sc`). A new area needs a join row first and the builder refuses to write without one. | 2026-10-12 — first build |
| **Annually**, and in the same change as any new South Carolina layer or roster | `coverage-gaps.json` | This file is emitted from the guidebook's gaps block, and `build_coverage_gaps.py --check` compares the two on every pull request, so the file cannot drift from the record. The yearly clock is for the RECORD: `sc-municipal-officeholders` and `sc-school-board-members` rest on nothing having been read yet, and `sc-county-council` names ten county pages this project could not read on 2026-10-11 | 2026-10-11 (`sc-county-council` rewritten when the layer was built) |
