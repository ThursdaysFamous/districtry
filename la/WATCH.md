# WATCH.md — Louisiana's watch calendar and deferred measurements

Two things live here: *when to look* for boundary and roster changes in this instance's
sources, and the measurements this instance has taken but not yet acted on. The repo's
`docs/REDISTRICTING_RUNBOOK.md` is *what to do* when a boundary changes. Update the
"Last done" column each time you complete a row — a checkpoint with a stale date is a
checkpoint that didn't happen.

---

## Re-check plan for each data file the app reads

The three roster jobs are in the standing table above. The files below have no job, because a
weekly job on a boundary would almost always find nothing to change. Each row says what moves the
file and when to look. A builder's `--check` proves a file matches what it was built from; it
never proves the source is still current.

| Cadence | File | The clock, and why it is that one | Last done |
|---|---|---|---|
| **On 3 January 2027**, then annually when TIGERweb rolls its congressional vintage, and on any redraw | `congress-districts.json` | The switch to the 120th Congress's map is the dated row above. After it, the Legislature draws the map, so a redistricting act or a court order is the other clock | 2026-10-20 (built from the 119th Congress's map) |
| **Annually**, on any redistricting act or court-ordered redraw, and for Act 955 before January 2028 | `la-senate-districts.json`, `la-house-districts.json` | The Legislature draws both chambers itself, so the signal is a redistricting act rather than a commission calendar. A rebuild with `la/scripts/build_legislative_boundaries.py` re-runs its 2,000-point agreement gate and its 8 m fidelity ceiling | **_(never)_**, built 2026-10-20 |
| **Annually**, when TIGERweb publishes a new county vintage | `state-counties.json`, `metro-outline.json` | Both come from the same 64-parish TIGERweb fabric, and the outline is that fabric dissolved, so they share one clock. `la/scripts/build_metro_outline.py --check` tests the shipped ring against its 64 inside anchors and its outside anchors in Texas, Arkansas and Mississippi, so it would catch a lost parish and would not notice a redrawn line. Re-run `la/scripts/build_state_counties.py` and `la/scripts/build_metro_outline.py` against the new vintage and compare; `la-parish-districts.json` is witnessed against the parish file, so rebuild it after | **_(never)_**, built 2026-10-20 |
| **Annually**, with the `--survey` row above, and whenever a parish publishes a new map | `la-parish-districts.json`, `la-parish-district-parishes.json` | A parish redraws its own districts, usually after a census, and files the new lines with the Census only if it chooses to. The six drawn parishes' lines are the Census's January 1, 2026 edition. `--check` holds the file to its build record, the list's seats, the edition the card names and the Parish layer at 4,000 points; it never proves a parish has not redrawn since | **_(never)_**, built 2026-10-20 |
| **Annually**, and in the same change as any new Louisiana layer or roster | `coverage-gaps.json` | This file is emitted from the guidebook's gaps block, and `build_coverage_gaps.py --check` compares the two on every pull request, so the file cannot drift from the record. The yearly clock is for the RECORD: each gap rests on a measurement with a date, and a publisher that starts publishing moves that finding with nothing to detect it | 2026-10-20 (written with the instance) |
