# WATCH.md — Tennessee's watch calendar and deferred measurements

Two things live here: *when to look* for boundary and roster changes in this instance's
sources, and the measurements this instance has taken but not yet acted on. The repo's
`docs/REDISTRICTING_RUNBOOK.md` is *what to do* when a boundary changes. Update the
"Last done" column each time you complete a row — a checkpoint with a stale date is a
checkpoint that didn't happen.

---

## Re-check plan for each data file the app reads

The three roster jobs are in the standing table above. The files below have no job, because a
weekly job on a boundary would almost always find nothing to change. Each row says what moves the
file and when to look. A builder's `--check` proves a file matches what it was built from; it
never proves the source is still current.

| Cadence | File | The clock, and why it is that one | Last done |
|---|---|---|---|
| **Monthly**, by the source-freshness job, and after each decennial census | `tn-commission-districts.json` | **A COUNTY CAN REDRAW ITS DISTRICTS IN ANY YEAR**, not only after a census, and each files its plan with the state, so the Comptroller's statewide layer is where a change shows first. That layer reports the date its data was last edited, and `tn/scripts/validate_sources.py` compares it every month with 2026-09-10, the edit this file was built from, and warns in the monthly issue when it moves. Then re-run `tn/scripts/build_tn_commission_districts.py` (it re-checks the 95 counties, each county's 1..N numbering, Nashville-Davidson's 35 charter districts, the 25 m fidelity ceiling and the county witness), compare, move `edited_at_build` to the new date, and bump `cache_name`. `--check` holds the shipped file to the same structure offline | 2026-10-11 (built from the 2026-09-10 edit) |
| **On 3 January 2027**, then annually when TIGERweb rolls its congressional vintage, and on any redraw | `congress-districts.json` | The switch to the 120th Congress's map is the dated row above. After it, the General Assembly draws the map, so a redistricting act or a court order is the other clock | 2026-10-10 (built from the 119th Congress's map) |
| **Annually**, and on any redistricting act or court-ordered redraw | `tn-senate-districts.json`, `tn-house-districts.json` | The General Assembly draws both chambers itself, so the signal is a redistricting act rather than a commission calendar. A rebuild with `tn/scripts/build_legislative_boundaries.py` re-measures its 25 m fidelity ceiling | **_(never)_**, built 2026-10-10 |
| **Annually**, when TIGERweb publishes a new county vintage | `state-counties.json`, `metro-outline.json` | Both come from the same 95-county TIGERweb fabric, and the outline is that fabric dissolved, so they share one clock. `tn/scripts/build_metro_outline.py --check` tests the shipped ring against its 95 inside anchors, so it would catch a lost county and would not notice a redrawn line. Re-run `tn/scripts/build_state_counties.py` and `tn/scripts/build_metro_outline.py` against the new vintage and compare. `tn-commission-districts.json` is witnessed against the county file, so rebuild it after them | **_(never)_**, built 2026-10-10 |
| **Annually**, and in the same change as any new Tennessee layer or roster | `coverage-gaps.json` | This file is emitted from the guidebook's gaps block, and `build_coverage_gaps.py --check` compares the two on every pull request, so the file cannot drift from the record. The yearly clock is for the RECORD: each gap rests on a measurement with a date, and a publisher that starts publishing moves that finding with nothing to detect it | 2026-10-11 (rewritten for the commission layer) |
