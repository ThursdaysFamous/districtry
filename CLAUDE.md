This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

It holds the rules. **Why each rule exists, what each check found and the measurements behind them are in `docs/PROJECT_RECORD.md`**, which is what this file was until 2026-11-20 (421 KB). Read the record's section on a subsystem before changing that subsystem; search it by the script or engine block name. Add new history there, not here: a rule goes here in a sentence or two, its story goes there with its date.

## What this is

districtry: one static, dependency-light web app per state, all fifty states, in one repo. Click a point (or search an address) and it reports every civic district containing that point and who represents you there. Each state is a folder `<tag>/` that serves at `districtry.com/<tag>/`; the repo root holds the fleet landing page and repo-level files (`metros.json`, `sitemap.xml`, `robots.txt`, `CNAME`, `fonts/`, `scripts/`, `docs/`). Each instance has its own `<tag>/CLAUDE.md` with what is specific to it.

- **No build step, no framework, no server-side code.** Each app (styles, core, every layer module) lives inline in `<tag>/index.html`; `<tag>/sw.js` is its service worker; `<tag>/data/app/*.json` are runtime-fetched data files. Everything else is data pipeline, scrapers, generators or CI. The one back end is the short-link lookup in `services/link-lookup/` (a Cloudflare Worker at `lookup.districtry.com`, deployed by `deploy-link-lookup.yml` when main changes it).
- **Never re-add an app file to the root**, and never add a `data -> il/data` symlink (roster workflows gate on `git diff --quiet -- il/data/app/`, and git does not follow a symlink).
- **Whether an instance is dark is read from the deploy**: a `<tag>/**` line in `deploy-pages.yml`'s `EXCLUDES`, read by `dark_instances()` in `scripts/validate_instance_registration.py`. Never restate that rule in another script; import it. Going live adds the `metros.json` entry and the instance's column in `layer-concepts.json`.
- **Illinois coverage** is county by county: `DISPATCH_COUNTY_FIPS` and `METRO_COUNTY_FIPS` in `scripts/build_metro_outline.py` are the authority, `docs/COUNTY_STATUS.md` is generated from them (`scripts/build_county_status.py`, never hand-edit). Adding a county adds dispatch entries and roster rows, never new layers. Rules per county: `docs/EXPANSION_GUIDE.md` §3.5.1.

## Generated files: edit the source, regenerate, never hand-edit

Most reader-facing pages and every per-instance fact are generated, each by a script with a `--check` mode that CI runs. Edit the input and regenerate; a hand edit fails CI. The main ones:

- `metro-worksheet.json` per instance → `scripts/generate_metro_files.py` writes the `GENERATED:BEGIN/END` regions in `index.html`, `sw.js`, `sources.html`, `validate_index.py`, `smoke_test.mjs`, `README.md` and this file.
- `engine/` holds the ONE copy of every engine block → `scripts/compose_app.py` splices it into every instance's `index.html`, `sw.js` and sub-pages. Edit the block under `engine/`, never a fence inside an instance file. Never inline a city-specific value in an ENGINE block; add a variable to the instance's `METRO:BEGIN config` block. `docs/ENGINE_SYNC.md` has the protocol.
- Root pages: landing page (`build_landing_page.py`), coverage map (`build_coverage_map.py`), privacy page (`build_privacy_page.py`, measured from each app's shipped `index.html`), `/ai.html` (`build_ai_page.py`), `/help.html` (`build_help_page.py`), `/llms.txt` (`build_llms_txt.py`), manifest and launcher (`build_manifests.py`), `fleet-outlines.json` (`build_fleet_outlines.py`), share preview pages (`build_share_pages.py`), sitemap (`build_sitemap.py`).
- Per-instance pages: question forms (`build_question_forms.py`), officeholder tables (`build_officeholder_tables.py`), legislator pages (`build_legislator_pages.py`), concept pages (`build_concept_pages.py`), county pages (`build_county_pages.py`), results pages (`build_results_pages.py`), election notices (`build_election_notices.py`), history pages (`build_history_page.py`), district search index (`build_district_search.py`), ZIP index (`build_zip_index.mjs`), social cards (`build_og_image.mjs`, recorded in `districtry/og-images.json`).
- A weekly workflow that rewrites a file a generated page reads must regenerate that page in the same run and `git add` it; the gates fail a workflow that does not.
- A page a generator creates carries other generators' markers empty; each fills its own on its next run, so every `--check` passes in any order. A fence marker must be alone on its line.

## Running & testing

```bash
python3 -m http.server 8000                       # serve the repo root, open /il/
npm install playwright@1.56.1 && npx playwright install --with-deps chromium
BASE_URL=http://localhost:8000/il/ node scripts/smoke_test.mjs   # per instance: <tag>/scripts/smoke_test.mjs
python3 scripts/validate_index.py il/index.html   # the static merge gate, per instance
pip install -c scripts/requirements.txt jsonschema
python3 scripts/generate_metro_files.py [--check]
python3 scripts/compose_app.py [--check]
```

`.github/workflows/smoke-test.yml` is the source of truth for the full battery and its order; `.claude/skills/steward/SKILL.md` mirrors it as local commands with the reason for each gate. Enumerate the battery through that skill or `scripts/validate_gate_counts.py`, never a pattern of your own. MEASURED 2026-11-20: a static gate is one NAMED step in the `static` job, which is **161**; counted as script invocations the whole battery is **410 — 356 that need no browser and 54 that boot Chromium** (a smoke test per live instance, two root-page tests and two fleet probes). The steward skill mirrors it EXACTLY as of 2026-11-20, **410 invocations for 410** (`scripts/validate_steward_mirror.py` compares the two). Re-measure after every edit to the battery and every merge into a branch that touches it; never increment a remembered figure. `validate_gate_counts.py` prints the current values when they differ.

- `smoke_test.mjs` is one end-to-end script, not a framework; there are no individual tests to select.
- After a failure, re-run only what failed while you fix it.
- **In this sandbox Chromium cannot reach cdnjs** (it does not use the agent proxy), so Leaflet and MapLibre fail to load and the app never boots. A `SessionStart` hook runs `scripts/vendor_leaflet.sh`, which vendors them into each instance's gitignored vendor dir; the smoke tests serve them from there. This is environmental, not a code regression.
- Some smoke checks need `PW_EXPERIMENTAL_SERVICE_WORKER_NETWORK_EVENTS=1` to see a service worker's requests.
- Monthly, not in CI: `scripts/validate_sources.py` (upstream datasets superseded or gone) and `scripts/validate_card_links.py` (every URL a card renders).
- Reading CI on a pull request: use `pull_request_read`'s `get_check_runs`, never `get_status` (this repo's gates are check runs, which `get_status` cannot see). A zero read minutes after a push can be a race; page `actions_list` by `head_sha` before concluding no run exists. A pull request that conflicts with main gets no run at all; merge main in, never push an empty commit or close and reopen.
- A green workflow run is not evidence it did its work: forgiven steps are masked. Ask which steps ran (`scripts/workflow_run_evidence.py`).

## Architecture: stable core + pluggable layer modules

All inside each `index.html`, in one IIFE, ES5 style (`var`, `function` expressions). The contract and build log are in `docs/BUILD_PLAYBOOK_1.md`; `docs/DATA_LAYER_GUIDEBOOK.md` is the fleet layer inventory (update it in the same change as any layer add, rename or remove); `docs/EXPANSION_GUIDE.md` is the guide for any expansion or new concept (it holds the rules, the guidebook holds the record).

- **Core**: the Leaflet map, click-to-select and the geocoder, a global `state` `{selectedPoint, sequence, layersOn, ...}`, the layer registry and result-card framework, the selected-boundary highlight, URL-hash permalinks (`#p=lat,lng&l=wd,sb`, layers as permanent codes from `layer-codes.json`; the long `#point=…&layers=…` form opens forever). Debug namespace `window.ChiExplorer`.
- **Reuse the shared utilities**: `sanitize(str)` / `textContent` for every external string, `pointInGeometry`, `fetchJSONWithRetry`, `haversineMiles`, and the layer factories (`registerPolygonLayer`, `registerSchoolZone`, `registerCpsNetwork`, `registerIlgaChamber`, `registerNearestPointLayer`, `registerCountyLayer`). Follow the existing factory when adding a sibling.
- **A layer** is `registerLayer({ id, group, label, overlay: {load, style}, query(point, seq), render(result) })`, with optional `hoverName`, `pointOfInterest`, `coverage(point)` (outside it the layer hides without touching `state.layersOn`). Adding a county to a shipped concept is a dispatch entry, not a new layer.
- **Stale-async guard**: every selection bumps `state.sequence`; async work captures `seq` and bails when it changed. Preserve this anywhere you await between selection and render.
- **Per-layer failure isolation**: a layer whose source is down shows an error and Retry inside its own card and never throws into shared code.
- **Card order**: layer name, district identifier, then where a verifiable source exists the officeholder(s), office location, phone/e-mail, and a link to more detail. Known gaps go in the guidebook's gaps block and ship as `<tag>/data/app/coverage-gaps.json`.
- **Layer colours, widths and codes are fleet-wide**: one colour, fill and line width per concept in `layer-concepts.json`; one permanent code per layer id in `layer-codes.json` (never change or reuse a code). No layer dashes its own outline; a dash means the comparison tool.
- **Engine `qr-code`, `geometry-measure`, `vector-tiles`** are self-written and each held by a gate that runs the block as shipped (`validate_qr_code.py`, `validate_geometry_measure.py`, `validate_vector_tiles.py`).

## Data

- Most layers draw from committed PMTiles archives (`<tag>/data/app/tiles/`) or same-origin boundary files; some still fetch public APIs live. Tile archives, Census block populations and boundary files are copied to Cloudflare R2 and read from `files.districtry.com` on the live site (`engine/shared/files-origin.txt`, `scripts/sync_r2_files.py`).
- **Service worker**: boundary geometry is cache-first and reaches a returning visitor only through a `CACHE_NAME` bump (`check_cache_version.py` enforces it); rosters are network-first.
- **Scraper → builder pairs**: a `*_scraper.py` writes intermediate JSON, a `build_*.py` writes `data/app/*.json` with count guards and refuses to write when too few records resolve. `check_roster_retention.py` fails when a field stops being published.
- **Roster refreshes never commit to main**: each weekly workflow re-scrapes, rebuilds, validates and opens a pull request as `BOT_PR_TOKEN` (so CI runs on it). The county board jobs share `.github/actions/bot-pr`. If bot PRs stop showing checks, check that token first.
- The "verified" date lives in each `metro-worksheet.json` as `verified_date`.

## Honesty and data rules (non-negotiable)

- **Officeholder data is never guessed.** With no verifiable source, a card links to the official body instead of naming anyone. A seat a source shows vacant prints as vacant; one no source names prints "Not listed".
- **External strings are always sanitized or set via `textContent`.** Never splice scraped text into HTML or JS.
- **Contacts**: an official's own phone or e-mail ships wherever a government source prints it beside that official alone; printed beside two or more, or equal to the office's line, it is the office's. Never ship home or street addresses (not even in logs or errors), anything an official asked in writing to leave off, fax numbers, or anything from a non-government publisher. `scripts/validate_telephones.py` checks that every `tel:` dials one whole number.
- **A geographic claim about a coordinate gets a control before it is written down** (measure it; do not infer it from knowing the region). An API error is not an empty answer: raise on an `error` key.
- **Say what you mean**: when a literal phrase is available, use it. No metaphor or flourish in card text, gap records, docs, commits, PR bodies or comments. Reader-facing prose to Adam is plain language.
- Check anything written about this project's process against the history and the routines, not against a statement of policy in a doc.

## Fetching other people's servers

- **robots.txt is read before the first fetch of a host, by `scripts/robots_policy.py`** (RFC 9309; the one reader), with the exact client that will crawl (same User-Agent, same headers), and followed through redirects. `scraper_common.require_robots_once` is the one-line seam; `scripts/validate_robots_adoption.py` fails a new script that fetches without it.
- `User-agent: *` binds every client this repo sends; groups naming an AI vendor's crawler do not. A `*` disallow is obeyed. A 401/403 on robots.txt reads as no policy; a 5xx or network failure disallows all. A captcha or managed challenge is an access control and is never solved or worked around (`CHALLENGE_FRONTED_HOSTS`).
- **One-off reads in Adam's own Chrome** (Adam, 2026-11-25: "A read once, B go"): when a site refuses automated readers and a gap results, a thread may open its public page ONCE in Adam's Chrome (Claude in Chrome) and read it, including a robots.txt-disallowed page or a browser check that clears by itself. Stop at a captcha, a check that needs a click, or access denied. Never a weekly or scheduled source. `/ai.html` says so publicly; keep the two in step.
- **A refusal stops the fetch and never unpublishes what we already have** (Adam, 2026-09-19): carry the last-good record forward with a stamp saying when it was last read.
- A scraper starts with a districtry token. A browser string is allowed only where the host measurably refuses the token; record the measurement in the calling file, and never probe a second client on a host that already serves the first. Measurements live in `user-agent-measurements.json` (`scripts/probe_user_agents.py --check`).
- **A page that fills itself in is read through its own feed** before anyone records it as unreadable: find the feed and any key the page gives every visitor, fetch it the way the page does, compare with a browser, and open linked documents (render scanned PDFs). See `.claude/skills/outbound-ask/SKILL.md` §1.
- Never bulk-query per-voter lookups. Subagents that fetch hosts follow the same rules; brief them explicitly.
- This site's own `robots.txt` carries `Content-Signal: search=yes, ai-input=yes, ai-train=no, use=reference`.

## Merging and CI conventions

- A PR that changes what readers see needs Adam's explicit "merge". Behind-the-scenes fixes (CI, tests, sitemap dates) merge once green. Project memory holds the current merge rules.
- Never skip, disable or quarantine a test to get green. Shortfalls and exceptions are recorded in the gate's own table (`ACCEPTED_DROPS`, `ACCEPTED_SHORTFALLS`, `EXPECTED_UNREACHABLE`, ...) with a measured value, reason and date, and each such table fails when an entry stops describing the tree.
- Self-merging is limited to the Chicago city election night job; `build_ai_page.py --check` fails on any other workflow running `gh pr merge` that `SELF_MERGE` does not record.
- The traffic report's three daily fetches commit straight to main (`DIRECT_PUSH` in `build_ai_page.py` records why); every other workflow that pushes opens a PR.
- GitHub starts this repo's scheduled jobs hours late; never rely on cron times for ordering.
